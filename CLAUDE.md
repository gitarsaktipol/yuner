# FerTune — Ringkasan Proyek

Baca file ini dulu sebelum mengerjakan apa pun di repo ini.

## Apa ini

FerTune (dulu bernama "Yuner") adalah aplikasi musik pribadi milik Ferdi, dalam bentuk PWA (Progressive Web App) **satu file HTML tunggal, tanpa framework** (bukan React/Vue, murni HTML+CSS+JS vanilla dalam satu file). Bahasa antarmuka Indonesia. Bisa di-install ke layar utama HP dan jalan offline lewat service worker.

Nama "FerTune" = Ferdi + Tune.

## Struktur repo

```
index.html            <- SATU-SATUNYA file sumber aplikasi (semua HTML/CSS/JS ada di sini)
manifest.webmanifest  <- metadata PWA (nama, warna tema, ikon)
sw.js                 <- service worker untuk cache offline; CACHE name di dalamnya HARUS
                          dinaikkan versinya (mis. fertune-v2 -> fertune-v3) setiap kali
                          index.html/manifest/sw.js diubah, supaya HP mengambil versi baru
privacy.html          <- Kebijakan Privasi (wajib untuk Play Store); ditautkan dari footer aplikasi
fonts/                <- font Bricolage Grotesque (woff2, subset latin) + OFL.txt, lisensi Bravura (bentuk kunci G/F); disimpan sendiri,
                          TIDAK memakai Google Fonts (privasi: sebisa mungkin tanpa server pihak ketiga)
playstore/            <- bahan Play Store: PANDUAN-PLAYSTORE.md (langkah upload via PWABuilder/TWA),
                          deskripsi-toko.md, ikon 512, feature graphic 1024x500, screenshot/ (berbingkai),
                          raw/ (screenshot polos, juga dipakai di manifest), assetlinks-template/
                          (templat assetlinks.json; file aslinya ditaruh di repo website Gitar Sakti, bukan di sini)
icon-192.png, icon-512.png, icon-512-maskable.png, apple-touch-icon.png  <- ikon PWA
                          (desain "FT" gradasi ungu-pink-biru dengan motif not musik;
                          icon-192/512 = sudut membulat transparan, maskable = huruf diperkecil
                          ke zona aman 80% di atas latar gradasi, apple-touch = kotak penuh)
```

Semua logika JS ada langsung di dalam `index.html` (di dalam satu `<script>` IIFE besar di bagian bawah file). Tidak ada build step, tidak ada bundler — file `index.html` inilah yang langsung di-serve oleh GitHub Pages.

## Hosting & deployment

- Repo GitHub: `gitarsaktipol/yuner` (nama repo masih "yuner", belum diganti walau aplikasinya sudah bernama FerTune — belum diminta untuk diganti)
- Live di: **https://fertune.gitarsakti.com/** (sejak Nov 2026, diputuskan Ferdi: FerTune & website Gitar Sakti = situs TERPISAH): GitHub Pages repo ini (branch `main`, folder root) + file `CNAME` (`fertune.gitarsakti.com`) + `.nojekyll` (supaya `.well-known/` ikut tersaji); DNS di **Cloudflare**: CNAME `fertune` → `gitarsaktipol.github.io`, **DNS only / awan abu-abu** (proxy oranye bisa menyimpan `sw.js` lama). `gitarsaktipol.github.io/yuner/` otomatis dialihkan GitHub ke subdomain. Alamat lama `gitarsakti.com/fertune/` (dulu rewrite Vercel, sesi login terbagi) sekarang hanya DIALIHKAN ke subdomain (`vercel.json` repo website). Akibatnya: login FerTune TIDAK lagi otomatis sama dengan website (akun sama, masuk sendiri; Ferdi setuju), data localStorage/izin MIDI-mikrofon/PWA terpasang dari alamat lama tidak ikut (waktu itu hanya data uji coba Ferdi). Tombol `.gsback` "← Gitar Sakti" memakai alamat lengkap `https://gitarsakti.com/`.
- Tidak ada CI/CD, tidak ada build. Push ke `main` = otomatis live dalam 1-3 menit.
- **Setiap kali mengubah `index.html`, `manifest.webmanifest`, atau `sw.js`, WAJIB naikkan nomor versi `CACHE` di `sw.js`** (contoh: `const CACHE = 'fertune-v2';` -> `'fertune-v3';`), kalau tidak, HP yang sudah pernah install PWA-nya tidak akan mengambil perubahan (service worker akan terus menyajikan versi lama dari cache).
- Service worker: precache diambil dengan `cache:'reload'` dan file sendiri dicek ulang dengan `no-cache`, supaya versi baru tidak tersimpan dengan file lama dari cache HTTP GitHub Pages (±10 menit). Saat service worker baru mengambil alih, halaman otomatis dimuat ulang sekali (`controllerchange` di `index.html`), jadi pembaruan langsung terlihat.
- Ikon di layar utama (aplikasi terpasang) diperbarui oleh Android sendiri, bisa sampai ±1 hari; cara cepat: hapus ikon lalu pasang ulang.
- Deploy GitHub Pages bisa gagal (error 500 dari GitHub) atau macet di antrean berjam-jam; re-run yang macet tidak bisa dibatalkan. Cek di tab Actions ("pages build and deployment"). Cara paling ampuh: push commit baru ke `main` (memicu deploy baru). Terjadi Okt 2026 (PR #73).
- Ferdi mengerjakan lewat PowerShell Windows di folder lokal `D:\YUNER\yuner-pwa`, pakai `git add . && git commit -m "..." && git push` untuk deploy.

## Gratis vs Premium & Metronome (lihat `RENCANA-PREMIUM.md` untuk rencana lengkap)
- **Metronome**: bagian dari menu Tuner (tombol "Tuner | Metronome" di header, `setTunerMode`). BPM 30-240, birama 2/4 3/4 4/4 6/8, ketuk tempo, jadwal bunyi presisi lewat jam `AudioContext` (`metSched`, lookahead 120 ms). Berhenti saat pindah menu / halaman tersembunyi. Gratis. **Naik otomatis** (latihan kecepatan, diminta Ferdi Okt 2026; kartu `#metAuto`, centang `#maOn`): Tambah `#maStep` +1/2/3/4/5/10 bpm, Setiap `#maEvery` 10/20/30 dtk/1/2 menit (`MA_EVERY`), Sampai `#maTo` 30–240 (langkah 5; target lebih pelan = turun). Disimpan `yg.metAuto` (`maLoad`/`maSave`), objek `met.auto`. `metSched` menaikkan `met.bpm` di ketuk 1 birama pertama setelah `met.autoNext` (jam AudioContext), angka BPM berdenyut (`.bump`); status + bilah kemajuan `#maStat` diperbarui `maRender` (tiap 250 ms saat jalan): "Naik +5 bpm dalam 7 dtk · target 140" / "🎯 Target tercapai!". Berhenti → tempo kembali ke tempo awal (`met.autoFrom`) dan "Terakhir sampai X bpm". Supaya muat 360x640: Mulai + Ketuk tempo sebaris (`.metGoRow`), angka BPM diperkecil saat `.met.autoOn`. Kotak pilihan `.maRow select` membulat (radius 14, garis & bayangan `--pLilac`, latar `--panel`; diminta Ferdi: jangan kotak lancip). Uji `met.js`/`metfit.js`.
- **Hak akses**: `isPremium()`, `gatingOn()`, `GATING_ON` (sekarang `false` = semua terbuka). `applyEntitlements()` menyesuaikan tampilan; `guardEdit()`/`showPaywall(kunci)` dipakai titik penguncian (Latihan Custom & Partitur saya, Arcade, edit/simpan/impor/ekspor/akor/gambar di Partitur, cloud). Lagu contoh: `s0` (Twinkle), `b-mary` (Mary Had a Little Lamb, ditambahkan sekali lewat `yg.seedMary`). Lagu contoh berhak cipta (`b-kj432` KJ 432, `b-canon` Canon in D arr. lemontart, `b-cicak` Cicak-Cicak di Dinding A.T. Mahmud) DIHAPUS untuk Play Store (diputuskan Ferdi, Nov 2026): fungsinya dibuang, salinan di HP pemain dibuang saat aplikasi dibuka & tidak dipulihkan dari cloud (`DROP_IDS`). ### 1. Tuner gitar
- Deteksi nada real-time dari mikrofon pakai algoritma **YIN** (implementasi sendiri, fungsi `yin()`). Versi hemat: di sample rate ≥32 kHz sampel diperkecil 2x (rata-rata tiap pasang), berhenti di lembah pertama di bawah ambang 0,12 (tidak menghitung semua pergeseran sampai 60 Hz), lalu posisi lembah dihaluskan lagi di sample rate penuh (ketelitian sen tuner tetap). ±10–40x lebih ringan dari versi lama. `yin()` menyimpan jendela yang terakhir dianalisis di `yin.x/yin.n/yin.sr` untuk `heardTarget()`.
- Tuner memakai jendela penuh 4096 sampel (~85 ms, tenang); Latihan/Arcade hanya menganalisis ±43 ms suara TERBARU (`mic.recent`, ujung jendela) supaya petikan cepat terdengar.
- Jarum penunjuk sharp/flat, petunjuk teks "Kencangkan senar" / "Kendurkan senar", senar yang sudah pas ditandai hijau.
- Mode otomatis (deteksi senar mana yang dibunyikan) atau kunci ke satu senar tertentu.
- Tombol bunyikan nada acuan (referensi) per senar.
- 7 pilihan tuning: Standar, Drop D, turun ½ nada, turun 1 nada, DADGAD, Open G, Open D.
- A4 referensi bisa diatur 430-450 Hz.
- **Senar pas** (stabil di ±5 cent selama >0,7 detik, `stringTuned()`): bunyi "ting" lonceng (`ting()`, nada senar +2 oktaf), getar HP 60 ms, tulisan "Senar N sudah pas! ✓", pasak jadi hijau. **Keenam senar pas**: lagu kecil (`successChime`) + confetti + getar panjang + "Semua senar sudah pas! 🎉". Selama bunyi ting, analisis mikrofon dijeda (`toneUntil`) supaya ting tidak terbaca sebagai nada gitar. AudioContext dinyalakan di tombol "Aktifkan mikrofon" (`micStart` → `ac()`), karena browser HP memblokir bunyi yang tidak dimulai dari sentuhan.
- **Muat satu layar tanpa scroll** (diuji 360x640 s/d 412x915): ukuran huruf nada, jarum, tombol, pasak senar (`--pg`) & kepala gitar memakai `clamp(..vh..)` mengikuti tinggi layar. Di layar < 700 px tinggi (`@media (max-height:700px)`) label "Terlalu rendah/Pas/Terlalu tinggi" disembunyikan & judul diperkecil. Teks petunjuk dan tombol dibuat pendek (1 baris / 2 baris) — kalau menambah elemen di Tuner, cek ulang supaya tetap muat.
- **Nada "bayangan" diabaikan** (keluhan Ferdi, Nov 2026: senar A loncat-loncat setelah ±2 detik): nada ke-3 senar A (330 Hz) = senar E tinggi yang ikut bergetar; saat A melemah YIN membaca 330 Hz. Di `tunerData`, bacaan yang ±50 sen dari ×2/×3/×4/×½ median TANPA petikan baru (`tn.attackT`: volume melonjak >1,5× dalam 300 ms) dibuang (tidak memperbarui `lastHit`). Diuji sintetis (A 108 Hz + E4 ikut bergetar: dulu loncat ke 330 Hz di detik ke-3). Bantuan Tuner menyarankan meredam senar lain dengan jari.
- Smoothing pitch pakai median dari histori beberapa sampel + logika penolakan outlier (butuh 2x sampel menyimpang berturut baru dianggap ganti nada, bukan langsung reset di 1 sampel liar) — ini untuk mencegah jarum "lari-lari" karena noise sesaat.

**Tangga nada** (dropdown "Tangga nada" di Mode Latihan, disimpan di `yg.key`, berlaku untuk Acak/Arcade/Custom; untuk "Partitur saya" ikut kunci partiturnya):
- Disimpan sebagai `key` = jumlah ♯ (1..7) atau ♭ (-1..-7), 0 = C. Label pilihan mengikuti jenis notasi: not balok "♯", "♯♯", ... / "♭", "♭♭", ...; not angka "Tangga nada A (1 = A)".

Mekanisme penilaian not yang dimainkan (fungsi `practiceHit`):
- Mikrofon dianalisis tiap 25ms; onset (serangan nada baru) butuh jeda minimum 90ms dari onset sebelumnya. Syarat "volume sempat turun" (`dipped`) dinilai dari puncak/lembah SEBELUM bingkai saat ini (dulu sesudahnya: petikan yang lebih keras dari not sebelumnya & not pertama tidak pernah jadi onset, sehingga not sama yang diulang lebih keras tak terdeteksi dan not lain baru tertangkap lewat jalur legato ±100–200 ms kemudian).
- **Cara Simply Piano — mendengar not yang diminta** (`practiceTarget` -> `heardTarget(m,anyOct)`): setelah serangan baru, aplikasi mengecek apakah not yang SEDANG DIMINTA (semua nada akornya; gitar = tulisan −12) berbunyi, lewat kemiripan sinyal (NSDF) di periode not itu: puncak ≥0,86 dan letaknya dalam ±40 sen (bukan not tetangga), bukan oktaf bawah (puncak di 2T tidak lebih kuat) dan bukan oktaf atas (kemiripan di T/2 < 0,62). Kalau ya, atau YIN membaca nada yang sama, not itu jadi calon. Ini menolong suara piano/gitar asli yang tidak murni (YIN menolaknya, `yin.conf>0.1`), ruangan berisik, dan salah oktaf. `heardTarget` mengembalikan frekuensi terukur (0 = tidak terdengar); `practiceTarget` mengembalikan `{m,f}`.
- **Penyaring suara bicara DICABUT** (keputusan Ferdi, 26 Okt 2026): penyaring lama (2 pembacaan stabil `PD_STAB` + `struck()`/`attackMs` waktu naik ≤25 ms, PR #69) membuat not piano asli yang benar sering tidak terdeteksi walau volume besar. Ferdi menerima akibatnya: suara bicara bisa terbaca (sering sebagai salah). Sebagai gantinya, usul Ferdi: nada terukur yang berjarak **≥2 oktaf (24 semitone) dari SEMUA nada not yang sedang diminta diabaikan** (`practiceData`, selain filter rentang soal ±7). Kode `attackMs/struck/trackAttack/PD_STAB` sudah dihapus — JANGAN dipasang lagi tanpa persetujuan Ferdi. Uji sintetis: piano/gitar 10/10 (median ±70–105 ms); bicara tepat di nada not lolos ±40–60% (dulu 0–15%).
- **Not SAMA dipencet berulang** (keluhan Ferdi, Okt 2026): serangan ulang naik dari sisa dengungan not sebelumnya, sehingga syarat serangan `rms>2*min` dan turun-dulu 60% gagal. `pdRep(now)` = not yang diminta sama dengan not yang baru diterima (`pd.last`, ≤2,5 dtk): HANYA saat itu syarat dilonggarkan (serangan 1,3x, turun-dulu 75%). - **Impor lagu (audio) → MIDI → partitur** (`#saudIn`, `importAudio`, Premium dengan paywall `audio`; diminta Ferdi, Okt 2026, terinspirasi fitur "Any track to MIDI" YuE2-Studio — model MuScriptor di sana 0,4–5,5 GB & butuh GPU NVIDIA, jadi TIDAK disalin): memakai **Basic Pitch** (Spotify, Apache-2.0) yang jalan di HP lewat TensorFlow.js. File: `vendor/basic-pitch.js` (basic-pitch 1.0.1 + tfjs-core/converter/backend-webgl/cpu 3.21 + chained ops, dibundel esbuild IIFE → `window.FTBasicPitch`, ±830 KB) dan `vendor/basic-pitch-model/` (model.json + bin, ±0,9 MB); lisensi di `vendor/LICENSE-basic-pitch.txt`. Dimuat malas saat fitur dipakai (`loadBasicPitch`), lalu tersimpan oleh service worker (tidak di PRECACHE). Alur: `decodeAudioData` → mono 22050 Hz via OfflineAudioContext (maks `AUD_MAX`=120 dtk) → `evaluateModel` (persen tampil) → `outputToNotesPoly(…,0.5,0.3,5)` → `cleanNotes` (buang not <0,09 dtk & harmonik +12/19/24/28/31/36 dari nada lebih kuat yang bersamaan) → `guessBpm` (autokorelasi serangan, 60–180, condong ke 100) → not pertama digeser ke ketukan 0, not dipanjangkan sampai not berikutnya bila jeda ≤1 ketuk → `midiToScore` (melodi = nada teratas per 1/16) → `addImportedScore` (juga dipakai impor MIDI). Setelah selesai ada tautan "Unduh MIDI lengkap (semua nada)" (`notesToMidi`, polifonik). Uji sintetis: melodi piano/gitar satu alat → nada, ritme & tempo tepat; lagu dengan iringan akor → berantakan (keterbatasan; disebut di Bantuan). `privacy.html` menyebut audio diproses di perangkat.
- Tombol "Baca otomatis dengan AI" HANYA muncul kalau halaman dibuka dari tautan Claude Artifact (pakai jatah API Claude milik pengguna yang login), untuk membaca melodi satu baris dari gambar — hasilnya perlu dikoreksi manual, bukan 100% akurat.

## Detail rendering notasi

- Not balok (staff notation) dan not angka (numbered/jianpu notation) **digambar sendiri sebagai SVG** dari nol (fungsi `drawScore`, `noteSvg`, `numSvg`) — tidak pakai library notasi musik pihak ketiga (bukan VexFlow/abcjs/dll).
- **Kunci G & kunci F** (`CLEF_TREBLE`/`CLEF_BASS`) = bentuk asli dari font musik **Bravura** (Steinberg, SIL OFL 1.1, lisensi di `fonts/LICENSE-bravura.txt`), disalin sebagai path SVG (bukan memuat font): 250 satuan font = 1 spasi paranada (S=10 px → skala 0,04), titik nol kunci G di garis ke-2 dari bawah, kunci F di garis ke-4. Diminta Ferdi (Okt 2026) karena gambar kunci buatan sendiri kurang mirip aslinya.
- Not balok: not seperdelapan/seperenambelas yang berurutan dalam SATU ketukan digabung dengan balok (beam) alih-alih bendera terpisah (`gs`/`grp` di `drawScore`; arah tangkai ikut rata-rata posisi nada, balok kedua untuk 1/16; rehat memutus kelompok; beam tidak ikut berubah warna saat state benar/salah).
- Not angka: garis panjang (beam) untuk not 1/8 & 1/16 digambar **DI ATAS** angka (bukan di bawah — sempat diminta dipindah), garis-garis pendek yang berdekatan dalam satu ketukan disambung jadi satu garis menerus, bukan garis terpisah per not.
- Not angka bertitik (mis. 3 bertitik + 2 seperdelapan, `numSvg`): titik dijauhkan dari angka, diletakkan di dekat not berikutnya sejajar dasar angka, dan garis di atas not seperdelapan yang mengikutinya diperpanjang ke kiri sampai tepat di atas titik (`bm.dl`), sesuai tulisan tangan standar not angka. Titik not bertitik SELALU diberi garis di atasnya (`line.dotl`; ¼ bertitik 1 garis, ⅛ bertitik 2 garis), juga bila not sesudahnya bukan ⅛ — supaya "5 ." bertitik tidak tampak seperti not ½ (diminta Ferdi, Okt 2026).
- Not angka di baris yang DIRENGGANGKAN (kartu Partitur Saya, PDF, editor, piano 2 tangan; keluhan Ferdi Okt 2026 "0 0 0 0 terlalu mepet, titik 5· terlalu dekat"): jarak angka rehat 0 0 0 0, titik panjang (minim/semibreve) dan titik not bertitik mengikuti lebar not sebenarnya `bm.span` (2 tangan: `(L.end-L.off)*k`), bukan jarak tetap 26 px, jadi sejajar ketukan tangan lain. `bm.gL/gR/dl` (garis beam & perpanjangan ke titik) memakai jarak sebenarnya ke not sebelum/sesudah. Not balok tidak berubah (reg: 0 beda).
- Layar lebar/miring (lebar > 600 px): `drawScore` menggambar dengan lebar virtual `W = lebar/scale` lalu SVG diperbesar seragam (`scale` maks 1,9) lewat viewBox — jadi garis, kepala not, dan jarak ikut membesar (bukan hanya melebar ke samping). Layar tegak tidak berubah. **Editor Partitur** memakai `drawEditorScore` (diminta Ferdi, Okt 2026: "masih intro sudah sebesar satu halaman"): kalau tinggi partitur > ±70% tinggi layar, skala diturunkan bertahap 0,15 (lebih banyak birama per baris) sampai minimum 1,0 di layar lebar / 0,85 di HP (`drawScore.force`). Juga dipakai pratinjau rekam.
- Not angka piano 2 tangan: jarak baris kanan–kiri dirapatkan (`botM` kanan 24, `topM` kiri 34+tumpukan akor) dan antar sistem diberi tambahan 26, supaya pasangan kanan/kiri jelas terbedakan dari sistem berikutnya. Kotak sorotan not tangan kanan di sini dipendekkan (`bm.hb`=24, bawaan 40) supaya blok/sorotan tangan kanan tidak tampak ikut menutupi baris tangan kiri (keluhan Ferdi, Okt 2026).
- Garis paranada digambar hanya sampai garis birama terakhir baris itu (`lineEnd` di `drawScore`), bukan sampai tepi layar — supaya di layar lebar/miring tidak tampak ada birama kosong ekstra.
- Titik oktaf di not angka (di atas untuk oktaf tinggi, di bawah untuk oktaf rendah) posisinya menyesuaikan supaya tidak bertabrakan dengan garis beam.
- Kursor/kotak penunjuk di editor Partitur digambar di **ruang kosong setelah** not/slot yang dituju, bukan menimpa langsung notnya — supaya jelas mana yang sudah diisi vs yang akan diisi berikutnya.
